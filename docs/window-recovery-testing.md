# Проверка восстановления окна Windows

Геометрия Windows проверяется в физических пикселях через `window_ext`.
`windowProps.positionScale` хранит масштаб при сохранении `left/top`.
Старые записи без масштаба интерпретируются с масштабом стартового окна,
затем проверяются и при необходимости центрируются на основном мониторе.
Размеры остаются логическими. Другие настройки не сбрасываются.

## Автоматические проверки

Без установки/обновления зависимостей:

```sh
flutter test --no-pub test/common/window_geometry_test.dart test/common/window_props_test.dart test/common/window_native_adapter_test.dart test/common/window_restore_test.dart test/widgets/windows_startup_gate_test.dart test/common/tray_test.dart
```

Тесты проверяют геометрию, сохранность конфигурации, порядок placement/show,
скрытый запуск, отсутствие сохранения временной геометрии, сбой получения
дисплеев, доступность интерфейса во время старта и блокировку его управления.
Они не заменяют сборку C++ и проверку Flutter/DWM на Windows.

## Ручная матрица (Windows 10/11)

- Один монитор: холодный запуск, перемещение, размер, полный выход, перезапуск.
- Два монитора: окно на каждом мониторе, справа/слева/сверху; повторить 10 запусков.
- Масштабы 100/100, 100/150, 150/100, 125/200%; отрицательные координаты.
- Отключить второй монитор до запуска, затем во время работы и при скрытом окне.
- Сменить основной монитор, разрешение, DPI, положение панели задач.
- Окно между экранами: смежные рабочие области и промежуток между экранами.
- В копии тестовой конфигурации задать огромные координаты, отсутствующую одну
  координату, неверный тип/размер. Проверить сохранность профилей и подписок.
- Свернуть/развернуть/полноэкранный режим: normal geometry не перезаписывается.
- Повторный запуск при видимом, скрытом, свёрнутом окне и при задержанном старте.
- `silentLaunch`: автоматического показа нет, открытие из трея работает.
- Замедленное/недоступное ядро: окно видно, подключение недоступно до окончания
  восстановления состояния. Ошибка видима; повторный запуск не создаёт второй UI.
- Ошибка до runApp: error screen; автоматический показ только когда настройка
  silentLaunch уже прочитана и равна false. При неизвестной настройке — явная активация.
- Минимум 380×600 сохраняется, кроме экрана с меньшей рабочей областью.
- Smoke-тест Linux/macOS и отдельного окна редактора.

Критерий: окно доступно, заголовок не потерян; корректная позиция сохраняется;
скрытое окно при изменении дисплеев не показывается. В системе без доступных
рабочих областей сохраняется нативная позиция, выполняется повторная проверка
при событии дисплеев или явном открытии.

## Диагностика

Основной лог: каталог `logs` в каталоге данных приложения, строки `[startup pid=…]`.
Ранний нативный лог: `%TEMP%\GektusClashX-startup-0.log` … `-7.log` (ограниченные
слоты по PID; при следующем запуске слот перезаписывается). Скопировать сразу
после инцидента. Каждый слот содержит фактический PID и системное время tick.

- `geometry before/after`: физические bounds, DPI, visible/minimized/maximized,
  рабочие области; решение preserved/clamped/primary fallback.
- `show requested/complete`, `hide requested`: намерение и фактическая видимость.
- `first Dart post-frame` и `first native Flutter frame`: отдельные этапы кадра;
  сами по себе не доказывают успешную композицию DWM.
- `… begin/complete/failed/still waiting`: последний незавершённый startup-этап.
- `single-instance acquired/refused`, `existing instance owner=…`: повторный запуск.
- `render paused/resumed`: ручная приостановка кадров.

Внеэкранное окно: visible=true, не minimized, нет пересечения bounds с рабочими
областями. Скрытое: visible=false. При доступных bounds и пустом содержимом
проверять этапы первого кадра, сообщения engine/GPU и отзывчивость процесса.
Не отправлять полную конфигурацию: достаточно windowProps, silentLaunch/autoRun,
схемы экранов, версий Windows/приложения/драйвера и диагностических логов.
